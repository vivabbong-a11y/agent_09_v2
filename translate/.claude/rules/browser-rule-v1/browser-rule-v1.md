# 브라우저 제어 규칙 (v1)

이 규칙은 이 프로젝트에서 웹 브라우저를 열거나 제어할 가능성이 있는 모든 작업에 적용됩니다.

## 1. 기본 도구

- 모든 브라우저 작업에는 **Playwright MCP**(`mcp__playwright__*` 도구)를 사용합니다.
- 다른 브라우저 도구(예: Claude in Chrome, `mcp__claude-in-chrome__*`)는 사용자가 명시적으로 지정한 경우에만 사용합니다.

## 2. 트리거 키워드가 있으면 자동 호출

사용자의 메시지에 다음 키워드(또는 이와 분명히 같은 뜻의 표현)가 들어 있으면 동의를 묻지 않고 바로 Playwright MCP를 호출합니다.

- "브라우저를 열어서", "브라우저 열어", "브라우저로"
- "웹 제어", "웹제어", "웹 자동화"
- "직접 작업", "직접 해줘", "직접 들어가서"
- "사이트 들어가서", "페이지 열어서"
- 영어 표현: "open the browser", "control the web", "do it yourself in the browser"

키워드는 브라우저를 여는 것에 대한 동의로 간주하지만, 작업 전체에는 CLAUDE.md의 작업 방식(todo list 먼저 보고, 승인 후 실행)이 그대로 적용됩니다.

## 3. 키워드가 없으면 먼저 동의 구하기

트리거 키워드가 없더라도 Playwright MCP로 처리하거나 확인할 수 있는 작업이라면 — 예: 실제 웹페이지 확인, 스크린샷 촬영, 폼 입력, 로그인이나 JavaScript 렌더링이 필요한 페이지 읽기, 업로드한 게시물 점검 — 임의로 호출하지 **않습니다**.

1. 이 작업을 브라우저로 할 수 있다는 점과 브라우저에서 무엇을 할지 사용자에게 알립니다.
2. 동의를 구합니다(예: "브라우저를 열어 직접 확인할까요?").
3. 사용자가 동의한 뒤에만 Playwright MCP를 호출합니다. 거절하면 다른 방법(예: WebFetch/WebSearch)을 쓰거나 한계를 설명합니다.

한 작업에서 받은 동의는 다음 작업으로 이어지지 않습니다.

## 4. 브라우저 제어 중 안전 수칙

- 되돌리기 어렵거나 외부에 영향을 주는 동작(결제, 삭제, 게시, 메시지 전송, 폼 제출, 계정 설정 변경) 전에는 멈추고 다시 확인을 받습니다.
- 비밀번호나 결제 정보를 사용자 대신 입력하지 않습니다. 로그인은 사용자가 직접 하도록 합니다.
- 일부러 차단형 대화상자를 띄우지 않습니다. 대화상자가 나타나면 `browser_handle_dialog`로 처리합니다.
- 같은 단계가 2~3번 실패하면 계속 재시도하지 말고 멈춘 뒤 사용자에게 진행 방법을 묻습니다.
- 스크린샷과 로그는 사용자가 보관을 요청하지 않는 한 산출물 폴더가 아닌 scratchpad나 `.playwright-mcp/`(git 제외)에 저장합니다.
- 작업이 끝나면 브라우저를 닫습니다(`browser_close`).
