# 조사 노트: AI 에이전트란? (네이버 블로그 글용)

- 날짜: 2026-10-24
- 목적: 네이버 블로그 글 「AI 에이전트란?」의 근거 자료 (원고는 `blog/ai_agent/`)

## 1. 정의

- IBM: AI 에이전트는 "사용 가능한 도구로 워크플로우를 설계해 자율적으로 작업을 수행하는 시스템"입니다. 언어 처리를 넘어 의사결정, 문제 해결, 외부 환경과의 상호작용, 실제 행동까지 수행합니다. 에이전트는 "사람이 정한 목표와 사전 규칙이 필요"합니다.
- Anthropic(「Building effective agents」): *에이전틱 시스템*을 포괄 용어로 씁니다.
  - **워크플로우**: 미리 정의된 코드 경로에 따라 LLM과 도구가 조율되는 방식
  - **에이전트**: "LLM이 자신의 과정과 도구 사용을 동적으로 지시"하며 작업 방법을 스스로 통제하는 방식
- 국내 블로그·WikiDocs의 쉬운 설명: 일반 AI는 "물어보면 답하는" 존재, 에이전트는 "알아서 일을 처리하는" 존재(계획 → 도구 선택 → 실행 → 결과 확인 → 재시도).

## 2. 에이전트의 작동 방식 (IBM)

1. **목표 설정과 계획** – 사람이 목표와 규칙을 정하고, 에이전트가 목표를 하위 작업으로 나눕니다.
2. **도구를 활용한 추론** – 외부 데이터셋, 웹 검색, API, 다른 에이전트로 부족한 정보를 채우고 계획을 재평가·수정합니다.
3. **학습과 반성** – 사람이나 다른 에이전트의 피드백을 활용하고 배운 내용을 저장합니다.

흔히 쓰는 4요소 단순화: **LLM "두뇌"(추론·계획)**, **인식**, **도구**, **기억(단기·장기)**이 인식 → 계획 → 행동 루프를 목표 달성까지 반복합니다. 이 분류는 표준이 아니라 단순화된 설명입니다.

## 3. 챗봇 vs 워크플로우 vs 에이전트

| | 챗봇 | AI 워크플로우 | AI 에이전트 |
|---|---|---|---|
| 핵심 동작 | 질문에 답변 | 정해진 단계를 따름 | 목표를 향해 다음 단계를 결정 |
| 유연성 | 낮음 | 낮음~보통 | 높음 |
| 예측 가능성 | 높음 | 높음 | 낮은 편(검증 필요) |
| 적합한 일 | 질의응답, 초안 작성 | 반복적이고 명확한 작업 | 열린 문제, 여러 단계 작업 |

Anthropic의 조언: 가장 단순한 방법부터 시작하고, 예측 가능성이 중요하면 워크플로우를, 단계 수를 예측할 수 없는 열린 문제에는 에이전트를 씁니다. 에이전트는 성능 대신 지연 시간과 비용을 치르며 오류가 누적될 수 있습니다.

## 4. 에이전트의 종류 (IBM, 단순 → 고도화)

1. 단순 반사형 (타이머 온도조절기)
2. 모델 기반 반사형 (청소한 구역을 기억하는 로봇청소기)
3. 목표 기반형 (경로를 찾는 내비게이션)
4. 효용 기반형 (시간·비용·연료를 따져 최적 경로 선택)
5. 학습형 (개인 맞춤 추천)

## 5. 도입 현황

- 가트너(보도자료, 2025-08-26): 2026년 말까지 기업용 애플리케이션의 40%에 특정 업무용 AI 에이전트가 탑재될 전망이며, 2025년에는 5% 미만이었습니다. 가트너의 발전 경로: 내장형 어시스턴트 → 특정 업무용 에이전트(2026) → 멀티 에이전트 생태계(2029). 최상의 시나리오에서 에이전틱 AI는 2035년 기업용 애플리케이션 소프트웨어 매출의 약 30%(4,500억 달러 이상)를 차지할 수 있습니다.
- 벤더 블로그의 시장 규모 수치는 편차가 커서 글에는 사용하지 않았습니다.

## 6. 위험과 한계 (IBM)

- 멀티 에이전트 간 의존성과 같은 기반 모델의 공통 약점
- 무한 피드백 루프(같은 도구를 반복 호출)
- 연산 비용과 시간
- 데이터 프라이버시·보안 ("실험적이고 종종 예측 불가능한 동작" 때문)
- 국내 블로그의 실무 팁: 권한(읽기 전용인지, 수정·전송·삭제가 가능한지)을 확인하고 사람의 검토 단계를 둡니다.
